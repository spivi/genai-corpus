# genai-corpus

Shared corpus loaders and the twelve-line cost-ledger schema for the *Generative AI
Engineering* series on [spivitz.com](https://spivitz.com): every unit repo in the
series pins this package to a commit SHA instead of duplicating the loading,
checksum-verification and cost-accounting code eight times over.

This repo holds a small **fixture corpus** (`fixtures/corpus/`) used by CI and local
tests only — synthetic, non-media stand-ins for the loader's shape. The real ~5 GB
frozen corpus (`v1.0`, checksum manifest) is generated by `SPZ-45` and published as a
Hugging Face dataset; it never enters this git history. See `.gitignore` for the media
extensions this repo refuses to commit, by design rather than by convention.

## The cost ledger (`SPZ-44`)

`genai_corpus.ledger.CostLedger` is the schema every unit's build must emit, and
`validate_ledger()` is its enforcement: a raw dict missing a field, carrying a field
of the wrong type, or inventing a field outside the schema raises
`LedgerValidationError` naming exactly which field is wrong. The twelve line items the
M4 plan mandates (hardware, model and precision, input/output size, assets processed,
embedding/generation calls, metered tokens, GPU/CPU active time, storage/egress,
cache-hit rate, cost per result and per 1,000, quality metric, failure rate) become
eighteen typed fields — several items are inherently a pair of measurements. Every
field is required to be *explicit*: a measured value, or the `NOT_APPLICABLE`
sentinel — never a bare zero standing in for "didn't measure this." `per_unit_metrics`
is the escape hatch for anything unit-specific, addable without editing the schema.

`genai_corpus.ledger_table.render_ledger_markdown_table()` turns a validated ledger
into the two-column table an article publishes — the only path from ledger to table,
so drift between the two is structurally impossible rather than merely discouraged.

## The Modal harness (`SPZ-44`)

`genai_corpus.modal_harness.run_and_measure(call, hardware)` runs a zero-argument
closure once (typically `lambda: some_fn.remote(x, y)`) and returns the result
alongside the measured GPU seconds, CPU seconds, and dollar cost — one call in, one
measurement out, so cost capture is never a step an author has to remember separately.
`capture_library_versions()` reports the interpreter/package versions a run used, for
the ledger's `library_versions` field (M4 plan Risk 4: a dated claim about what ran is
reproducible fact only if the versions are pinned and recorded, not remembered).

`weights_volume()` is the one sanctioned place a later GPU unit writes model weights —
a persistent Modal `Volume` mounted at `WEIGHTS_VOLUME_MOUNT_PATH`. No function in
this package writes a weight file to local disk, and the repo's `.gitignore` refuses
every weight-file extension as a second, independent guard.

`scripts/hand_run_spz44.py` is the one hand-run this ticket's acceptance criteria
mandate: a single CPU call to a trivial probe function, executed by hand against live
Modal, its emitted ledger committed at `fixtures/ledgers/spz-44-hand-run.json`. It is
never invoked by CI or any test — `modal` is a pinned dependency (vetted through
`/dependency-guard`: ALLOW, no CVEs, no typosquat match, `modal-labs/modal-client`
provenance confirmed) so the package imports cleanly with no credential, but no
automated path in this repo ever calls Modal, so no automated trigger can spend money.
That hand-run cost **$0.0000465** (3.55 measured CPU-seconds on Modal's CPU rate).

## Install

Pinned to a commit, from any consuming repo's `pyproject.toml`:

```
genai-corpus @ git+https://github.com/spivi/genai-corpus.git@<commit-sha>
```

Never pin to a branch: a moving dependency would mean a unit's published ledger
numbers were measured against code that no longer exists.
